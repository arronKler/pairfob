# 通知

默认关闭。打开后，Agent **等你处理**或从工作中变成**完成**时，会推到已订阅的设备。点通知回到**那台电脑的那个会话**，而不是只打开首页。

完成通知只认 `working → done`。pairfob 刚启动时即使读到已经完成或正在等你的会话，也不会补发旧通知。

当前不区分通知类型：「等你处理」和「已完成」会一起订阅，不能分别设置。同一会话的状态更新会替换旧通知，完成后不会在通知栏里留下过时的「等你处理」。

没有通知也能用 Pairfob：打开网页或主屏幕图标，列表里「等你」的卡片仍然醒目。

## 电脑上打开

启动 `pairfob` 的环境里设置：

```sh
PAIRFOB_PUSH=1
PAIRFOB_VAPID_SUBJECT=mailto:you@example.com
```

`PAIRFOB_VAPID_SUBJECT` 必须是你能控制的 `mailto:` 或 `https:` 地址。不要用随手编的邮箱。

安装脚本装上的用户服务**不会**自动带上这两个变量。需要写进服务环境后再重启：

```sh
pairfob service restart
```

## 手机上订阅

1. 电脑端已经打开推送，并且服务已起来
2. 打开 Pairfob → 设置 → 通知
3. 「打开通知」可点时再按
4. 浏览器会问一次系统权限

电脑端还没开时，按钮显示「电脑端未开启」，下面有一段电脑设置说明。不支持网页通知的浏览器会直接说明，不会假装订阅成功。

设置页会直接显示这台手机是「打开通知」还是「通知已开启」。

## 点开通知之后

应进入对应的会话。若那个会话已经不在了，会回到列表并提示「这条通知对应的会话已经不在了」。

## 关通知

- 手机：在系统设置里关掉该站点的通知，或解除这台手机的配对
- 电脑：去掉 `PAIRFOB_PUSH=1` 并重启服务。已有订阅不会再发出「等你」或「已完成」推送

丢失设备先 [解除配对](/zh/devices)，不要只关通知。
