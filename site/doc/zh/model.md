# 同一块屏幕

Pairfob 不是在浏览器里再画一遍 xterm，也不是远程桌面。它读电脑上已经渲染好的 pane，把按键打回 PTY。两边看见同一块屏幕。

Herdr 仍在你电脑上跑。云上的 `pairfob.com` 只做 relay，不跑 agent，也不解析会话内容。

```
打开 / 点 / 打字                 同一 pane
手机  ─────────────────────────►  电脑 Herdr
              密文经 relay
```

## 产品循环

真正想保住的不是「手机上也能看终端」，而是这一圈：

1. 电脑上 agent 在跑
2. 它停下来等你（可选：推一条通知）
3. 打开的是**该** pane，不是首页凑合一下
4. 对话框可点，不盲发 Enter
5. 系统键盘把字打回本机 PTY
6. 画面确认已经落地
7. 坐回电脑前，接着就是这一步

coding agent CLI 当时有的能力，这里才有；没有的不画。详见 [能力从哪来](/zh/capabilities)。

## 因此

- 出门打开，就是电脑上那个会话
- 坐回来不用同步、不用关远程窗口
- 手机上改的布局就是电脑上的布局
- 没有「手机专用精简命令集」

这不是镜像一份副本。手机上的窗口和电脑上的窗口是同一个。

## 和常见方案比

| | Pairfob | 网页终端 | 远程桌面 | 云端 agent |
| --- | --- | --- | --- | --- |
| 会话在哪 | 你的电脑 | 往往另开一条 | 整台桌面 | 别人的机器 |
| 看到什么 | 已渲染 pane | 新的终端缓冲 | 像素 | 另一份聊天 |
| 回来要不要合并 | 不要 | 常常要 | 要面对两套操作 | 两套上下文 |
| 家里开端口 | 不要 | 视方案 | 常见 | 不要 |
| CLI 能力 | 以 live Herdr 为准 | 取决于你贴进 PTY 的东西 | 完整桌面，过重 | 产品自己的子集 |

## 刻意不做的事

- 不在浏览器里解释 ANSI、不仿真 curses
- 不把 Herdr HTTP / Unix socket 暴露给中继
- 不在手机上重做一套 agent 运行时
- 不把焦点抢回电脑前台
- 不提供任意命令、删 worktree、或整页布局覆盖

路径和 cwd 必须落在 live snapshot 根或 `PAIRFOB_ALLOWED_ROOTS`；失败时 fail-closed，不会改去猜一个成功结果。
