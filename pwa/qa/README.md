# Deterministic PWA parity fixtures

This directory is a Vite development HTML entry. It is not referenced by `pwa/index.html` or the production build, and it is excluded from the production bundle. It never imports `src/main.ts`; session calls are local stubs and all unmocked application fetch/WebSocket calls are blocked, so no production RPC or stored credential is ever used.

The fixture mounts the SAME stable production App (`src/app/mount.tsx`) with the production session-owner seam (`src/features/session/register.ts`) and explicit browser adapters. There is no legacy DOM renderer, no duplicate shell orchestrator and no production paint bridge: a scene change resets named domains through typed fixture actions, commits once through the real commit boundary, and the App composes the page from the prepared frame. A scene reset never unmounts the running App and never clears production subscribers. The only deliberate remount boundary is the standalone shell fixture (`terminal-loading` / `terminal-error`), which renders the production `FullTerminalScreen` component through its OWN QA-owned React root — not the production screen bridge/legacy root — and explicitly unmounts that root before the App claims `#app` again. Validate the fixture with `bun run typecheck:qa`.

Use a dedicated browser context and the same browser version, installed fonts, timezone (`UTC` recommended), language and viewport on both sides of a comparison. The current typed fixture depends on the stable App (`src/app/mount.tsx`) and must NOT be copied over an immutable historical checkout: that checkout keeps and serves its OWN historical fixture/adapter as it existed at its commit. Run each checkout's own QA entry for its side of the comparison; the existing saved baseline artifacts (56 scenes × zh/en × mobile 390×844 / desktop 1280×900; 224 screenshots) stay unchanged and are never regenerated by overwriting the historical tree.

Wait for `window.qa` and then `await window.qa.ready`, or wait for `html[data-qa-ready="true"]`. No fixture toolbar is rendered. Example browser evaluation:

```js
await window.qa.ready;
window.qa.scenes; // Names and descriptions for every supported state.
await window.qa.setScene("workspace-diff");
window.qa.snapshot();
```

`setScene` serializes changes and tears down the PREVIOUS scene (terminal, guided scroll, board scroll, dialogs, compose drafts, trace caches, board previews, pending workspace requests and call logs) before resetting named domains for the next one. The reset also returns what the workbench scenes raise: live input and the key pad go back to their baseline, the open-order stamps are forgotten in memory and in the fixture's storage, the inspector closes with the session it sat beside (its own lifetime, not a fixture switch), pinned diff notes are cleared, and an open React modal such as search and jump is closed through its own close handler rather than removed from under React. The current scene's terminal/session stay live until that teardown. It waits for pending-skeleton reveal when relevant, fonts and animation frames. `setLanguage("en")` resets the current fixture scene in the requested locale. Viewport comes entirely from the browser; `desktop-*` names do not force width. Resize through the browser to exercise the real 900 px breakpoint.

The snapshot includes:

- Actual root React ownership and count of React-managed DOM elements, detected from runtime DOM instrumentation, plus the fixture mode (`react`) and the `shellOnly` flag for the two standalone shell scenes.
- App/body/root classes, phase/screen, viewport and timezone, and document/app horizontal overflow.
- Rectangles for core shells, scrollports, panes, compose pads and dialogs.
- Stable input node IDs, values, focus, and selection. Compare IDs before/after interactions in the same scene to detect remounts; IDs across page loads are unrelated.
- All read, mutation, lifecycle and attempted network calls, plus runtime error/unhandled-rejection messages.

Interaction controls:

```js
window.qa.clearCalls();
window.qa.hold("promptAgent");
// Drive the actual visible send button using the browser.
window.qa.calls; // Exactly the calls made by the UI.
window.qa.release("promptAgent");
window.qa.failNext("workspaceDelete", "unknown_outcome");
window.qa.setConnected(false); // Fixture connection and network flags; no real transport.
window.qa.appendChatTurn(); // Append one bounded, deterministic backend turn.
await window.qa.refreshChat(); // Call the production refreshAgentTrace path.
await window.qa.render();
```

For the renderer fixture with a blank terminal, select `terminal-live`, wait for a recorded `terminalOpen` and a hidden `.full-terminal-state`, then send a local frame with `window.qa.terminalFrame("\u001b[2J\u001b[Hpairfob renderer QA\r\n")`. `terminal-frame`, `terminal-wide` and `terminal-inspector` arrive drawn and are ready only once the screen has been delivered and the grid has stopped changing; `terminalFrame` still injects further frames on top. The helper returns false if no local terminal is open; options accept `full`, `sequence`, `cols` and `rows` for stale/gap/resize probes. Terminal IDs change on each local open. `terminal-open-error` rejects the first local open, allowing retry with the real renderer. All of them use the real xterm/WebGL modules and production terminal event/visibility handlers; the session RPC and frame source remain local stubs. No socket or PTY is involved.

`emit(event)` only emits to subscribers on the fixture session; it does not simulate the production socket handshake. `appendChatTurn()` changes the bounded local trace backing store without rendering, while `refreshChat()` invokes the production `refreshAgentTrace` controller and records the resulting `agentTrace` read. Together they test refresh publication and ownership, not a socket reconnect. Fixture results are deterministic and reflect return shapes at the session API boundary. They are not a second implementation of the daemon. Some mutations update local snapshot data (rename/close, board layout operations, and a workspace file delete or rename, which leaves or renames the entry in the fixture's listing so the list's next state can be walked); other create/workspace mutation responses are logged canned results, so this is a UI call-count and ownership harness rather than backend semantics validation.

Important gaps and limits:

- `terminal-loading` and `terminal-error` are marked `shellOnly=true`: they deliberately render the production FullTerminalScreen shell with an inactive engine (no xterm, no TerminalOpen) to verify shell/control React ownership and visual parity. The shell renders through a QA-owned standalone React root with an explicit create/unmount lifetime (never the production paint bridge or its global legacy root), and that root is retired before any ordinary scene remounts the App. WebGL/frame behavior and terminal bridge lifecycle are covered by `terminal-live` / `terminal-open-error` (real engine in the browser; mock engine in the bun smoke).
- Camera is deterministically denied, clipboard is local, Notification permission requests return denied, credential IndexedDB is blocked, and no real push subscription/handshake/pairing is performed. Add separately authorized live/device checks for these paths.
- Seeded scenes cover page states, not every modal or control combination. Open existing menus, operation forms, diff-note editors, help dialogs and file confirmations via browser interactions on these scenes. Search and jump is the only dialog with scenes of its own; other declarative modal scenes, update-in-progress fixtures, live viewport keyboard simulation, and full native-device IME/pinch/foreground checks remain to add. The Phase 2 long trace is deterministic fixture coverage, not a real-runtime stress result.
- Date/Date.now are fixed at `2026-09-08T04:00:00.000Z`; monotonic gesture/timer clocks remain real. A scene that seeds stamps the application takes from `Date.now()` itself (`home-recent`'s opens) does it through `clockAt` (`qa/environment.ts`), which holds another instant for one synchronous action and returns to the fixed one. Animations/transitions and caret paint are disabled without changing the browser motion preference or layout rules. This is static geometry/color parity, not animation acceptance.
- When recording acceptance evidence, keep source/test, rendered fixture, live transport and physical-device results distinct.


The board scenes (`board`, `board-busy`, `board-zoomed`, `board-offline`) keep a
split tree per tab (`qa/board-layout.ts`) and publish herdr-shaped `splits`.
Split, resize, swap, zoom/restoration and close follow herdr 0.9's layout rules
(resize moves the split on the pane's requested edge, else the opposite one,
right/down by +amount and left/up by −amount, clamped to 0.1–0.9). They are a
deterministic stand-in for PWA feedback and target identity, not a substitute
for checking against a real Herdr.
Use `hold("resizePane")`, `failNext("resizePane", "unknown_outcome")`, and
`setConnected(false)` to check busy, ambiguous-result, and reconnect behavior.
Long-press input must use real browser touch events; invoking the menu directly
only tests presentation. After opening or submitting a dialog, wait for the
expected dialog or updated tile before taking the next snapshot.

`chat-preview` exercises chat file references and the real HTML preview component.
Its HTML is larger than 128 KiB, with local CSS imports, SVG, ES modules and JSON,
an interactive counter, a download, and DOM/storage isolation probes. The preview
iframe deliberately fetches `http://localhost:5173/qa/preview-api` (CORS allowed)
and `/qa/preview-no-cors` (CORS denied); these are Vite-only fixture endpoints.
The top-level QA environment still blocks unmocked application networking. Browser
checks should cover 390×844 touch, 820×900 touch, 1024×768 touch and 1440×900
mouse/keyboard, including Source/Preview state retention, source-line links,
Reload, and returning to the original chat. These are fixture checks, not a real
daemon/relay or physical-device acceptance result.

The HTML preview also exercises P2P admission and page-lifetime content caching:
reload or close/reopen a report and inspect `workspaceMediaOpen` versus
`workspaceMediaRead` counts. Unchanged dependencies are opened for validation
without chunk reads. Emit a relay latency event to retire the preview and show
the P2P notice; Source remains available. Emit a P2P latency event to restore it.
A source-line link must not open media until Preview is selected. These fixture
checks complement the real encrypted relay admission and transport-switch tests.
