# 桌面回显示波测试

在登录了图形桌面的 macOS 14.4+ 上运行。需要 Swift 编译器、项目指定的 Go 工具链和可用的 H.264 硬件编码器。

```sh
./scripts/desktop-latency/run.sh
```

在本机浏览器打开终端输出的完整链接，点「连接 Mac」。Mac 会出现带移动蓝条的黑色窗口；点击「翻转」或按空格后，窗口和浏览器接收的画面应一起变色。点「连续测 30 次」可用随机间隔重复测量。P50、P95 是本次连接中所有成功翻转的最近秩分位数；一次超时会标记失败并结束该连接。点击「断开」释放窗口和编码器。切换测试档位需重新连接。按 Ctrl-C 关闭服务。

同网手机需要能直接访问 Mac 的局域网地址和 WebRTC UDP 端口。使用可信局域网，在项目根目录执行：

```sh
./scripts/desktop-latency/run.sh -listen "$(ipconfig getifaddr en0):18797"
```

如果本机已经配置了指向当前局域网 IP 的测试域名和有效证书，手机可用 HTTPS 入口。以本仓库的 LAN 开发证书为例：

```sh
./scripts/desktop-latency/run.sh -listen lan-dev.pairfob.com:18801 \
  -media-listen lan-dev.pairfob.com:18802 \
  -cert .dev/acme/certificates/lan-dev.pairfob.com.crt \
  -key .dev/acme/certificates/lan-dev.pairfob.com.key
```

手机打开终端打印的带片段链接。每次启动生成新令牌，同时可连接一台设备。若浏览器要求安全上下文，启动时加上 `-cert /path/to/chain.pem -key /path/to/key.pem`，使用设备信任且主机名匹配的 HTTPS 地址。局域网 HTTP 仅供这个专用测试窗联调；信令经过本机 HTTP，媒体和翻转命令经过 DTLS-SRTP / DataChannel。双方仅使用 host ICE，不配置 STUN、TURN 或 Pairfob relay。指定 `-media-listen` 时，主机在该端口同时接受直接 UDP 和 ICE-TCP，浏览器通过 ICE 选择路径，页面显示选中的协议。HTTPS 页面与媒体使用不同端口。窗口捕获限定为当前进程自己的窗口，输入端仅接受固定的翻转命令。

测量链路为浏览器事件或自动触发 → DataChannel → 主机测试窗变色 → ScreenCaptureKit → VideoToolbox 硬件 H.264 → Pion RTP → 浏览器解码 → 读取中心像素。显示的毫秒数包括浏览器检测回调和像素读取。自动触发不含物理输入采样，视频帧回调也不能证明面板已发光。物理测量需将同步输入 LED 与接收端屏幕中心放入同一高速摄影画面。移动蓝条用于让主机持续产生视频更新；这两档规定输出尺寸和请求帧率，实际采集、解码帧率要看统计。测试窗内容简单，结果不能代表整屏游戏负载。

实验独立于产品连接，用本机信令直接建立一个 peer，同时承载视频和测试输入。这里可验证采集／编码／解码和像素回显。生产方案中的设备认证、独立媒体连接、跨 NAT 成功率和真实 DO 计数需要产品集成后另测。

## 首次本机测量（2026-11-18）

M3 Pro、macOS 26.6.2、同机 Ego Chromium，ICE 选中 host ↔ host。每个档位重新连接后自动翻转 30 次。播放帧率和接收缓冲为该轮结束时的统计窗口，非整轮平均数。

| 请求档位 | 已识别的翻转 | 软件回显 P50 | 软件回显 P95 | 接收帧率 | 接收缓冲 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1920×1080 / 60 | 30 / 30 | 803.0 ms | 900.9 ms | 58 fps | 13.4 ms |
| 1280×720 / 120 | 30 / 30 | 819.7 ms | 945.1 ms | 53 fps | 5.6 ms |

早期试跑还出现过首帧和单次回显超时。改用持续运动的合成器图层后，两档各完成一轮。另在 390、820、1024 像素宽的 Chromium 触控模拟视口各验证了一次触摸翻转。此处尚无实体手机、持续 120 fps 或物理 input-to-photon 的验收数据。单次接收缓冲读数无法解释整段回显延迟。

## 分段复测与回调偏差（2026-11-18）

同机 Chromium 的一次 4.1 秒观测里，视频回调的 presentedFrames 从 15 增到 219，页面收到 8 次 requestVideoFrameCallback。等回调才读像素，会把页面调度等待算进回显。在同一连接同时采样同一播放器，短时轮询确认了全部 30 次翻转，回显为 36.4–247.1 ms；该轮回调观测的 P50 为 818.8 ms。另取主机真实编码输出，用 FFmpeg 逐帧解码 240 帧，黑到白和白到黑都在采集器标记的首帧出现。

测试页保留视频帧回调，同时在等待首帧或翻转回显时每隔约 8 ms 补读播放器中心像素。只计入确认发生的黑白变化。浏览器计时器也可能晚调度，读像素本身有耗时。使用 `/?callbackOnly#本次令牌` 可仅用原回调复测；两种方式读同一视频元素，计时终点相同。

点「导出最近样本」可保存这次连接最近 1000 次输入的 JSON。每行以 id 关联，不需要对齐 Mac 和手机的时钟。没有观测到的阶段省略。elapsed 缺失是未完成的样本。

| 字段 | 单位与含义 |
| --- | --- |
| ack | 从浏览器发出翻转，到收到 Go 已写入原生组件输入管道的确认，单位 ms，包含双向传输和两端调度 |
| schedule / capture / encode | Mac 单调时钟的三段 ms：原生读取命令到开始更新窗口、开始更新到采集回调确认中心亮度改变、确认变色到该帧编码完成回调 |
| frameNotice | 从浏览器发出翻转到收到主机已向 RTP 写入变色帧的旁路通知，单位 ms，包含通知回程 |
| decoded | 从浏览器发出翻转到独立解码帧读出目标亮度，单位 ms。浏览器支持 MediaStreamTrackProcessor 时采集 |
| elapsed / readback | 浏览器软件回显总 ms，以及其中最后一次读取播放器中心像素所用 ms |
| observer / callbackGap / presentedBetweenCallbacks | 完成像素确认的采样来源；包围输入时刻的两个已观测回调间隔 ms 与呈现帧计数增量（若可用） |
| sourceRtp / videoRtp | 源端首个变色帧与确认回调关联的 RTP 时间戳，单位为 90 kHz 时钟 tick。计时器读像素时没有对应回调时间戳 |

用同一测试窗仅比较 VideoToolbox 的速度优先提示，顺序为开启、默认、默认、开启；每种配置每轮每档观察 30 次变色帧编码。1080p 默认的编码 P95 为 45.3 / 37.5 ms，开启为 22.3 / 13.0 ms；720p 默认 8.9 / 10.2 ms，开启 8.3 / 8.0 ms。原型现在优先编码速度，硬件不支持该提示时继续用默认配置。复杂桌面内容的画质和码率仍需单独验证。

回归检查可运行 `node --test --test-timeout=3000 scripts/desktop-latency/observer.test.mjs`，覆盖有画面变化但无视频回调，以及迟到回调导致重复计数的情形。

### 最终候选的三轮浏览器实测

同机、host ↔ host、每档三次重新连接，每次 30 个随机间隔的自动翻转。合并行按每个样本重新计算最近秩分位数。

| 请求档位 | 成功数 | 软件回显 P50 / P95 | 解码变色 P50 / P95 | 编码 P50 / P95 | 三轮回显 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1080p60 | 90 / 90 | 131.5 / 392.0 ms | 90.7 / 403.8 ms | 12.0 / 77.4 ms | 750.0 / 375.1 / 356.0 ms |
| 720p120 | 90 / 90 | 71.0 / 344.7 ms | 40.4 / 399.6 ms | 6.5 / 14.6 ms | 287.9 / 344.7 / 373.9 ms |

首档三轮结束时浏览器接收窗口显示 48、55、50 fps；第二档为 100、107、88 fps。两档均未达到 20 ms P95。分段会重叠，不能相加；播放器和解码观测都包含浏览器调度及诊断读回的开销。编码提示的收益来自独立主机对照，浏览器前后的测量口径发生了变化，不能把全部差额归因于编码优化。实体手机、物理显示和持续高运动内容待验收。

手机能看到页面时，点「连接 Mac」后观察按钮下方的阶段。1/4 为本机收集候选地址，2/4 为信令和令牌验证，3/4 为 ICE 和 DTLS，4/4 表示通道已经打开、正在等视频。主机终端记录页面请求、鉴权结果、peer 状态和数据通道打开事件。

### 首次手机回显实测（2026-11-18）

用户在实体手机上成功连接，报告测试页的播放器像素回显 **P95 为 109.4 ms**。该值覆盖浏览器发出翻转到读回变色像素。当前记录缺少手机型号、编码档位、样本数、实际 ICE 协议及逐次分段数据；物理触摸到屏幕发光仍待测量。
