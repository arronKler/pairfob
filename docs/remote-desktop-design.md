# Pairfob 远程桌面设计提案

用户在 Pairfob 的机器页点「远程桌面」，看见这台电脑当前的桌面，用手指、键鼠或外接键盘操作它，随时切回原来的终端。第一版建议做 **macOS 被控、手机／平板／桌面浏览器主控、1080p60 办公**。同步做 720p120 的低延迟实验。Windows 游戏串流单列里程碑。本文中的接口、性能数字和门槛均为设计目标。独立原型及本机实测见[桌面回显示波测试](../scripts/desktop-latency/README.md)。

UU 远程提供的多屏、手柄、按键映射、文件传输、远程唤醒和隐私屏可作为体验参照。Pairfob 的优先级是从正在处理的机器一键进入桌面，可靠地完成点击、拖动、输入中文和切屏。游戏支持还需要相对鼠标、帧间隔稳定和主机侧手柄设备，不能凭播放器支持高帧率就宣布完成。[网易 UU 远程](https://adl.netease.com/d/g/uuremote/c/brand_broadcast1)

当前工作区已接入 macOS 13+ 被控端和机器页入口。启用方式、四个已实现的 RPC 和媒体格式见[远程桌面协议](../proto/remote-desktop.md)。[浏览器验收夹具](../pwa/qa/README.md#remote-desktop)使用合成画面，便于复查直连、音视频、输入、缩放和断连。此前手机记录的 P95 109.4 ms 来自独立延迟原型；正式链路的操作到画面延迟待真机测量。

## 一次远控会话怎么建立

```text
手机／平板／电脑                                 被控电脑
Pairfob PWA ─ 原有配对及直连升级 ─ Worker / DaemonRoom ─ daemon
            ╰─ 已认证的直连 DataChannel ────────────────╯
               能力、授权、桌面 SDP、键鼠、停控
            ╰─ 按需创建的第二条 WebRTC 直连 ────────────╯
               视频 H.264、系统声音 Opus、RTCP 反馈
                                                │ 本地用户会话
                                        桌面采集／硬编／系统输入
```

现有客户端在 relay 上建立 Established 会话，交换加密 SDP，完成新的 DeviceHello、TransportCommit 和直连 Ping 后关闭手机侧 relay socket。现有 Pion 接收端只接受一个有序可靠的 pairfob DataChannel。文件下载已有客户端和 daemon 双侧限制 P2P 的先例。[直连契约](../proto/direct-transport.md) · [Pion 接收端](../cmd/pairfob/p2p.go) · [文件下载契约](../proto/workspace-download.md)

1. macOS 交互安装时提供无人值守设置，也可以在首次开启时办理。用户一次性选择显示器、查看或控制范围并授予系统权限。此后已配对设备（含以后配对的设备）可在该范围内直接连接，授权跨重启保留，直到本机修改或关闭。
2. 机器页读取现有 GetConfig。新增可选能力按具体操作命名，如 `view_desktop`、`control_desktop`、`listen_desktop_audio`。旧 daemon 缺字段即不可用。全局直连开关、客户端 relay-only 偏好、主机策略任一禁止时，显示原因和可用操作。
3. 客户端等当前主会话完成直连证明，在直连上获取可选显示器并请求打开。daemon 从真实连接取得设备、route 和权限，分配短时会话；按保存的授权自动启动采集。主机默认同时服务一个桌面观看者和至多一个控制者。第二个设备看到占用，当前会话结束后可重新连接。
4. 浏览器创建只接收媒体的 PeerConnection。offer 与 answer 经第一条直连的 Pairfob AEAD 传递。双方各自生成临时证书，用受认证 SDP 中的 DTLS 指纹验证媒体对端。两端只使用 host、srflx、prflx 直连候选；独立验证第二条连接成功，首个可显示视频帧到达后才开放输入。
5. 独立媒体连接允许关闭桌面、切换编码和回收 GPU，而不重协商原有终端连接。代价是第二次 ICE/DTLS、额外 STUN 请求和独立拥塞控制。两条连接可能走不同网卡，主连接直连成功不能当作媒体直连成功。原型单列第二次协商耗时、失败率和文件下载争带宽，作为是否需要改成同一连接的决策依据。
6. 主连接回落 relay、用户改选 relay、主机锁屏／切换用户、授权撤销或设备解绑时，主机终止桌面并释放按键。原有终端按其既有策略恢复。媒体路径中断时立即冻结输入、提示「画面已中断」，超时回收资源。重新进入须取得新会话，过去的输入和授权请求均不重放。

### Relay 成本如何验收

给定相同的基础 Pairfob 会话和同一恢复策略，打开桌面、看半小时、移动鼠标或上传文件应产生 **0 个桌面专属 Worker 请求、0 条桌面 relay 消息、0 字节桌面 payload**。不部署 TURN、SFU、录制存储、桌面心跳或诊断上报服务。所有桌面请求在客户端**入发送队列前和出队时**校验已绑定的直连 epoch；通用 RPC 恢复队列不得携带它们。daemon 按实际入口再次拒绝 relay 上的桌面操作。Worker 继续只转发不透明帧。

沿用现有直连尝试次数和退避；点击桌面不会开第二个 relay socket，或为了桌面在 relay 上持续轮询。若两端 NAT 或防火墙阻止直连，展示「这两个网络之间无法直连」，允许更换网络后重试，也可返回终端。首次连接、普通恢复以及更多用户使用产品带来的基础信令仍可能影响总账单。取消媒体中转保证的是每分钟远控不会在 relay 累积流量。[Durable Objects 计费维度](https://developers.cloudflare.com/durable-objects/platform/pricing/)

成本测试用同一对设备、相同拨号和断网脚本对照“仅终端”和“终端＋桌面”。在测试端按 route/操作归因，DO 测试边界只数帧长、消息、请求与连接存活时间。分别覆盖启动、稳定串流、媒体失败、强制回落和 30 分钟持续输入。示例：10 Mbps 视频运行半小时约 2.25 GB，应全部由两端直连承载。发布时再比对每千次基础会话的请求和 DO 时长；额外 STUN 探测单列。

## 主机、媒体与输入设计

| 主机 | 采集、编码和回放声音 | 输入和交付边界 |
| --- | --- | --- |
| macOS 首发 | ScreenCaptureKit 采集选定显示器和可选系统音频，CVPixelBuffer 交 VideoToolbox 低延迟 H.264，系统音频转 Opus | 在登录用户会话里通过系统辅助功能授权发送键鼠。录屏、辅助功能分开引导。用真实安装服务核实 TCC 归属、拒绝、撤销和签名升级后的行为 |
| Windows 第二阶段 | DXGI Desktop Duplication，D3D 表面交硬编，WASAPI loopback；验收旋转、显卡切换和全屏应用 | 用户会话代理使用 SendInput，尊重 UIPI 与安全桌面。当前项目仅支持 macOS 和 Linux。先交付 Windows 可配对宿主、安装／更新和用户会话生命周期，再开放被控。[当前平台支持](../README.md) |
| Linux 后续 | 优先 Wayland ScreenCast portal 和 PipeWire，探测可用硬编 | RemoteDesktop portal 授权输入，按桌面环境列支持矩阵。无图形会话时展示不可用 |

主机采集器只接触已获准的本地图形会话，通过受当前用户权限限制的本地 IPC 或进程内接口向 daemon 交付编码单元；daemon 拥有授权、网络和租约。先在 macOS 比较进程内与签名用户会话组件，按发布包的 TCC 归属、原有跨平台构建能否复现和拷贝开销选定。原生组件随版本签名校验，崩溃时父进程回收控制权。Pairfob Desktop 继续作为 Herdr 客户端，不作为采集的安装前提。[ScreenCaptureKit](https://developer.apple.com/documentation/ScreenCaptureKit) · [VideoToolbox 低延迟编码](https://developer.apple.com/videos/play/wwdc2021/10158/) · [DXGI](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api) · [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) · [RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)

**画面。** 初始办公档 1080p60、H.264 SDR、试验区间 6–12 Mbps；弱网档 720p30，低延迟档从 720p120 开始。按接收端 codec/profile、分辨率、真实解码帧率与主机硬编能力协商。关闭 B 帧重排和编码前瞻；编码器前只留最新待编码帧，发送端有界 pacing，过载时先丢未编码旧帧。处理 PLI 请求并对关键帧限频；避免任意丢预测帧造成整段花屏。客户端让浏览器直接呈现视频；静止文档降低采集／发送频率，滚动或输入后立即恢复。办公档优先文字清晰，快速运动档优先帧率。按 RTCP 丢包、带宽反馈、编码耗时和客户端掉帧降码率／分辨率，持续稳定后逐档恢复。系统声音由用户点按启用，可独立静音，切换音频设备重建音轨；比较启用声音前后的视频播放缓冲。

**输入。** 一期键、按钮、滚轮及文本提交走原有 AEAD 直连，设有界的专用输入调度，批次带序号和新 operation_id；接收端按会话串行应用，客户端可连续发批，不按一次 RTT 等一次确认。键与按钮边沿保序，合并未发送的绝对移动；按钮事件携带当下位置。滚轮合并增量，拖动保留按下和松开两端。可靠链路已排队的数据无法撤回，限制单批、限制在途量、对并行文件传输限速并测试队头阻塞。超过输入时延预算先停控并清空队列。若游戏档仍不达标，再单独评审媒体连接上的无序移动通道、独立认证及防重放协议；保持现有 envelope 和其有序序号语义。

高频输入需要独立评审执行路径。现有通用变更会持久化操作账本，逐次移动落盘会引入磁盘延迟。建议仅在不可恢复的控制租约内，以单调批序号、有界内存去重与新 operation_id 执行瞬时输入；daemon 重启即销毁租约并拒绝所有旧批次。授权、持久设备策略仍沿用现有账本。验证故障注入下的重复／过期拒绝以及磁盘写入频率，再开放高帧率输入。[现有操作账本](../internal/daemon/operations.go)

**坐标与焦点。** 主机下发显示器 ID、逻辑／物理尺寸、旋转、缩放和几何版本。客户端扣除黑边、缩放和平移后发送归一化屏内坐标；主机按版本映射，版本过期拒绝输入。拔屏或切屏先松键，等新画面再恢复。仅在远控画布持焦时接管硬件键，提供清晰的退出捕获入口和快捷键面板。中文输入使用 IME compositionend 一次提交，物理键组合另走键码，防止双输入。预测光标只用于指示本地指向；主机回传实位纠偏，避免与视频内光标重复显示。

## 用户在不同设备上怎么用

| 场景 | 交互与完成条件 |
| --- | --- |
| 手机 | 默认为触控板模式，单指移动、点按左键、长按拖动、双指滚动。可切换直接点选模式，捏合放大、平移后准确点中小按钮。浮层提供右键、滚轮、Esc、修饰键、显隐软键盘、适屏与退出；手指目标至少 44px |
| 平板 | 触控沿用相同手势，横屏支持沉浸查看，接上键盘或鼠标就按真实输入切换。缩放、软键盘、旋转只调整本地取景；默认保持被控显示器分辨率 |
| 桌面浏览器 | 鼠标绝对定位、左右中键、滚轮、拖动、组合键与全屏，离开画布还原本地快捷键。系统或浏览器保留的组合键通过显式工具栏提供可支持的等价动作 |
| 质量和恢复 | 默认「自动」，可选「文字清晰」「低延迟」、声音、显示器。展开诊断才显示当前直连、实际分辨率／fps、码率、网络 RTT 与丢帧；停止更新的画面覆盖中断状态，禁止盲点 |
| 多显示器 | 一次传选中的一屏；列表展示本地主机授权的屏名与尺寸。画面、输入坐标、系统声音来源随会话一致切换。后续多屏同时观看须分配共享码率预算 |
| 剪贴板和文件 | 文本以用户手动发送／取回为起点，按方向授权、限长，无后台监听。文件入口复用工作区允许根和现有传输能力；桌面入口只在直连上启用，传输显示进度、取消和限速。收发任意桌面路径需要独立的本地文件选择授权 |
| 游戏与扩展 | Windows 阶段增加指针锁定与相对位移、实体手柄、触屏按键布局、摇杆死区和布局保存。虚拟手柄驱动须完成签名、安装、卸载和兼容性验证。4K、HDR、高刷新率按设备组合逐项开放 |
| 后续独立能力 | 隐私屏需证明远端仍可看、现场有停止入口且异常退出能恢复；WOL 需同网段且已授权的在线唤醒节点或已有网络设施；无线副屏需要虚拟显示器。分别交付，不能依赖睡眠中的 daemon 提供连接 |

机器页同时显示「能看」「能控」及缺哪项本机权限。会话开始时被控机持续显示控制设备和本地停止按钮，并提供本机紧急停止快捷键；所有端都能主动结束。前后台切换、失焦、触摸取消及指针锁解除时释放所有远端按键。布局遵循现有宽度层级，操作按实际触摸、鼠标和硬件键盘决定。桌面视图打开时保留终端导航上下文，不调用 PTY resize。

## 协议、授权与资源回收

下面的名称用于评审。实现时在 proto/ 增加独立说明，为新操作添加严格 schema；现有操作字段、HKDF、AAD、DeviceHello、v1 envelope 与 v2 mux 全部沿用。媒体使用标准 DTLS-SRTP，信任根来自已认证直连内传递的双向 SDP；媒体连接只协商允许的轨道和方向。

| 拟新增操作 | 必要输入与约束 |
| --- | --- |
| DesktopSources | 已建立直连并通过查看策略，返回允许的源、几何版本、编码和声音能力 |
| DesktopOpen | 新 operation_id、source_id、请求的权限、接收能力及 SDP offer。使用持久授权校验访问范围，返回失败或短时 desktop_id。媒体启动后 answer 绑定本次 desktop_id、两个端点指纹与当前 route epoch |
| DesktopControlAcquire / Release | 新 operation_id，独立控制授权，授予单写者控制代次；原控制者退出时由主机清理所持按键 |
| DesktopInput | desktop_id、控制代次、序号、几何版本、operation_id 和有界 typed events；daemon 检查权限、重复／过期批、位置、频率和文本上限。局部注入失败即释放已按键并报告 unknown_outcome，只刷新状态 |
| DesktopSelectSource / SetQuality / Close | 修改使用新 operation_id；切源重新检查授权，结束须同时关闭采集、音轨、输入和媒体连接 |
| DesktopStatus / 租约 | 只走绑定直连；客户端前台、画面健康时续租。建议每 500 ms 续控制租约，连续 1.5 s 无续租由本地独立看门狗松键并停控；观看资源也设短时到期。限额、超时均由原型校准 |

每次操作由 daemon 将 desktop_id 与实际已认证的设备、会话、直连 epoch、允许源和授权范围匹配；仅持有 ID 不构成访问权。SDP 上限沿用 64 KiB，限制协商并发、媒体方向、候选类型和轨道数。权限撤销须主动终止现存流，不能等下一次输入；控制端失去首帧、卡死或隐藏后停止续控制租约。主机屏锁、显示器拔出、热切换用户由本地监听处理，立即停止发送旧桌面帧。主机可关闭无人值守授权，也可解绑单台设备。诊断只在端侧保存粗粒度时长、编解码、帧率、错误和启停审计；屏幕、按键文本、剪贴板、SDP 和地址不写日志。

实现前用上一已发布 PWA 做 GetConfig 兼容测试。当前 capabilities 的 JSON Schema 封闭；若旧版运行时也拒绝未知键，采用可选新操作进行客户端版本协商，只向明确支持新版的会话暴露新能力。新 PWA 在旧 daemon 上继续正常使用终端。对直接控制失败、权限拒绝、媒体协商失败和无编码器给出不同原因。

## 低于 20 ms 的定义和测法

用户按下物理按钮，到控制端屏幕指定区域**首次显示由远端应用产生的像素变化**，定义为端到端操作延迟。它包括输入采样、上行、主机应用响应、等下一帧、采集和编码、下行、接收缓冲、解码、合成及屏幕扫描。游戏自身每多排一帧也会算进去。RTT、本地光标、触摸涟漪或发送成功均不能替代这个数。

| 验收项 | 建议目标与适用条件 |
| --- | --- |
| 低延迟档 | 有线同一交换机、实测 RTT ≤2 ms、主机与客户端实际刷新均 ≥120 Hz、硬编硬解、轻量测试应用。挑战目标 input-to-photon **P95 <20 ms**。先测 720p120，分辨率、音频开关、设备型号逐项列出；未过线的组合不显示此承诺 |
| 办公档 | 同 LAN、1080p60、真实浏览器，目标 P95 ≤50 ms；持续运动 30 分钟，呈现帧间隔 P95 ≤25 ms，超过 100 ms 的冻结 ≤1 次／10 分钟。静止桌面的主动降帧单列 |
| 广域网 | 在 RTT 10／30／60 ms、丢包 0／1／3%、抖动和带宽阶跃下分别报告直连率、输入延迟和冻结；网络往返本身已用完预算时，显示实测 RTT，按实际画质档提供体验 |
| 启动 | 主会话已直连、已有本机授权下，点击到首帧 P95 ≤2 s 为目标。冷启动另列基础配对／直连、媒体 ICE、权限等待、首个关键帧各段；首次本机设置耗时单列 |
| 可用性 | 分同 LAN、家宽跨运营商、蜂窝到家宽、企业网、IPv6／双栈记录成功数／尝试数和首帧成功率，区分主通道失败和媒体单独失败。被阻断也计入分母 |

**20 ms 的工程预算。** 一个用于筛选设备的目标分配是输入采样与上行 2 ms、应用响应及等候采集 5 ms、采集与硬编 3 ms、下行及接收缓冲 2 ms、硬解 2 ms、合成及扫到测量点 5 ms，共 19 ms。它是预算，不是各阶段可独立达到的 P95，更不能相加得出端到端 P95。60 Hz 每帧约 16.7 ms，120 Hz 约 8.3 ms；随机相位、移动端触摸采样和浏览器合成很容易用完余量。若 LAN 有线基线已超标，优先看采集等待和显示队列，再用同一手机／平板比较 WebView 与原生解码呈现；仅在实测能缩短相应阶段时投入原生播放器。

**测量。** 用同步点亮 LED 的物理输入器，让被控测试应用收到按键后翻转固定区域；光电二极管或 ≥1000 fps 高速摄影同时记录 LED 与控制端该区域。固定屏幕测量位置，事件间隔随机化；每个设备／档位至少 500 次、3 轮，报告 P50/P95/P99、样本数、测量误差、掉样和失败次数。再跑真实编辑器打字、IDE 滚动、拖窗和游戏转向。触屏另量手指实际接触到远端反馈的路径。分别测试冷机和 30 分钟热稳定后的表现；接近 20 ms 且不确定区间跨线的结果不判通过。

诊断面板从 getStats 取选中候选对、currentRoundTripTime、丢包、帧数、解码耗时、接收端 jitterBufferDelay 等。累计量取时间窗差值并除以对应帧／样本数；缺字段显示不可测。主机用同一单调时钟记录采集回调、编码完成、发送；浏览器记录接收及可获得的呈现回调。跨设备时钟没有校准时只报各端局部耗时。功耗、温升、硬编占用和文件并发时的输入 P95 一并留档。[W3C WebRTC Statistics](https://www.w3.org/TR/webrtc-stats/)

## 实施顺序与发布门槛

| 阶段 | 交付 | 进入下一阶段的证据 |
| --- | --- | --- |
| A　测量原型 | macOS 真机采集、硬编、纯接收页面、最小按键回显、光电测量和 relay 帧计数 | 同机型比较 1080p60、720p120，有线和 Wi-Fi；报告首帧、端到端 P95、30 分钟温升和增量 relay 帧。由结果决定办公档、低延迟档和原生客户端投入 |
| B　邀请测试 | 默认关闭的只读桌面，再开放单控制者；交付完整授权、停止／撤销、三端键鼠触控、中文输入、诊断和断连回收 | 发布包实测系统授权；真实 iPhone、iPad、Android、桌面浏览器完成打开 IDE、输入中文、拖窗、旋转、切屏、锁屏与恢复；丢失松键、撤权后继续收帧、桌面流量进 relay 任一出现即阻断 |
| C　办公发布 | 多屏切换、系统音频、剪贴板、直连文件入口和自适应画质，按主机本地开关灰度 | 跨网络直连成功率与失败分布、旧 PWA／daemon 互通、断网恢复、并发传文件时键入和终端均可用、资源归零。发布已验证机型和性能区间 |
| D　游戏与更多平台 | Windows 被控、相对鼠标、手柄与按键布局，高刷／原生播放器；Linux 依 portal 能力逐步开放 | 每个平台用同一物理测量法重测；只发布通过测试的输入设备、显示模式及应用组合 |

代码落点建议：cmd/pairfob 管理 PeerConnection 和媒体 RTP，internal/daemon 管授权、operation ledger 和资源回收；独立主机采集模块持有 OS 句柄和编码器，避免 Herdr Runtime 接口携带桌面语义。pwa/src/lib/protocol 持有绑定直连的客户端，pwa/src/features/remote-desktop 实现画布与工具栏，机器路由负责入口。手机壳只在浏览器出现已量化的输入或呈现瓶颈时添加原生桥。发布包须包括可验证的组件版本、稳定签名和卸载路径；关闭主机功能即可停止新会话并回收活动会话。

验收增加协议与权限负例、旧代次输入、双设备争控、撤权、热插拔、后台和锁屏、强制 relay 回落、媒体崩溃、真实 NAT 以及可重复成本对照。浏览器夹具覆盖 390×844 触控、820 宽及 1024×768 触控、1440×900 鼠标键盘，并检查窄窗鼠标和横屏触控；真机、真实网络与实际安装服务分别记录。首次跨模块交付按仓库规则在最终候选上执行完整 verify；硬件延迟、TCC 和公网直连另附实测记录。
