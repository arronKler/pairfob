# Pairfob PWA React migration inventory

Read-only source audit, 2026-09-08. Repository: `/Users/bytedance/projects/test/pairfob`. Initial status contained only untracked `design/`; that directory was not read or changed. This report records source/test coverage, not a passing test run or browser/device acceptance. Source may change concurrently after this snapshot.

## Scope and completion requirements

The requested endpoint is the complete Vite PWA implemented with React + TypeScript + SCSS + Tailwind, preserving all existing behavior, interactions, and layout. A React root that merely calls the existing manual DOM screen renderers is an intermediate bridge, not completion. Third-party rendering surfaces (xterm canvas, video camera, sanitized Markdown) may remain imperative within React-owned host lifecycles. Protocol, transport, crypto, data caches, operations, and pure models can remain ordinary TypeScript.

Initial inventory: 162 production `.ts` modules, including 61 UI modules; 144 `.test.ts` files; 23 CSS files. Largest production files: `src/state.ts` 767 lines; `src/ui/agent-chat.ts` 754; `src/ui/full-terminal.ts` 721; `src/live.ts` 684; `src/ui/session/compose.ts` 613; `src/ui/workspace.ts` 569; `src/workspace.ts` 524. Each handwritten source/test/SCSS file must stay at most 800 lines. All paths below are relative to `pwa/` unless stated otherwise.

## Architecture and lifecycle map

- `src/main.ts` imports global styles and owns boot, connection restore, phases, responsive screen routing, global classes, language changes, visibility/network events, visual viewport hooks, delegated ripples, global keyboard handling, and swipe-back initialization.
- Phase union in `src/state.ts`: `boot`, `connect`, `pairing`, `resuming`, `live`, `pick`. Screen union: `home`, `pane`, `workspace`, `settings`, `quota`, `computers`, `board`.
- `src/paint.ts` exposes synchronous `render()` via `setRenderer()`. `main.ts` wraps renders in declared transitions. Callers currently depend on the DOM being updated synchronously after `render()` returns.
- Responsive precedence: workspace and board occupy their own shell; full terminal takes pane precedence; at widths >= 900 px the desktop rail/detail shell handles home/pane/settings/quota/computers. Mobile uses standalone pages. Full terminal does not live in the desktop side-by-side shell.
- `src/live.ts` explicitly distinguishes whole-screen rendering from `patchSessionScreen()`, `patchChromeTitle()`, `patchAgentChat()`, and `syncFullTerminalChrome()`. Snapshot updates and pane reads therefore do not blindly remount interactive fields.
- `src/ui/session/view.ts` performs in-place terminal row updates and preserves scroll and compose DOM. It skips row repaint while text selection is active. Whole-page rendering snapshots terminal scroll, mounts the new tree, restores scroll synchronously and on the next animation frame, then sizes/focuses compose.
- `src/ui/agent-chat.ts` keeps compose stable during trace updates; `patchAgentChat()` replaces only the stream and restores top/height anchors or follows the bottom. Cold history loading currently starts inside `fillAgentChat()`; move that fetch to lifecycle/controller orchestration, never React render.
- `src/ui/full-terminal.ts` owns singleton terminal, fit addon, observer, gesture/keyboard subscriptions, command pump, bridge version, renderer version, pending open tracker, frame gate and assembler. `renderFullTerminal()` patches an existing same-pane shell and returns without remounting; the first shell must paint before expensive xterm mounting. It uses session + pane + bridge generation checks for late async work.
- `src/compose-drafts.ts` + `src/state-drafts.ts` own drafts by daemon + pane + mode, plus view incarnation, draft revision and prompt lock ownership. These scopes are stronger than paneId alone and must survive component changes.
- `src/workspace.ts` owns independent view state and request versions with shared directory/file/Git caches in `src/lib/workspace-cache.ts`; it is not just a simple local component state.

## Highest-risk contracts and actionable migration constraints

1. **The same field means the same DOM node.** `src/ui/session/dock-pad.test.ts` compares node identity, activeElement, selection `[1,4]`, text and `state.composeIME` through expansion and pad changes; it explicitly expects zero top-level repaint. `src/ui/agent-chat.nav.test.ts` requires the same field across Enter and trace patch. `src/ui/full-terminal-compose.test.ts` checks stable focused input. Stable React keys must include daemon/pane/mode ownership and must not include unrelated revision, working state, pad state or screen read hash. Avoid assigning value or selection during active IME.
2. **Mutation effects cannot live in React render or remount effects.** SendText, SendKeys, PromptAgent, TerminalInput, workspace actions, worktree and object operations must remain explicit event/controller actions, preserving fresh operation_id and unknown_outcome handling. Repeated StrictMode mounts must not emit duplicate mutations or start duplicate terminal bridges.
3. **Synchronous paint calls carry ordering assumptions.** Many tests and controllers query DOM immediately after `render()`, then size/focus, show dialogs, or schedule mount. Bridge updates need a deliberate sync/commit strategy; eventually callbacks should operate on refs and post-commit layout effects. React view-transition update callback must resolve only after the intended DOM commit.
4. **Native event listener semantics matter.** `bindPadPress()` handles native pointerdown, document capture pointerup, cancellation, visibility and keyboard/AT click discrimination. React onClick-only conversion would duplicate physical key sends or lose rapid repeated taps. Preserve native gesture controllers under cleanup-capable effects unless ported with equivalent coverage.
5. **Terminal host is an owned resource.** Same-pane status, notices, language/pad changes and snapshots must not remount xterm. Switching pane/computer must retire old mounting/open/close/renderer ownership before new operations. Closing a pane waits for its pending terminal open/close; failures still allow only one pane mutation. Mount after visible shell paint, retain resize observation cleanup and frame/version gate.
6. **DOM-owned state must be elevated deliberately.** Agent details currently preserve `data-key`, `data-auto-open`, `data-user` states; workspace diff scroll is restored only for same path:layer key; board scale/pan and terminal follow/unread have explicit models. A fresh JSX tree cannot reset these on each poll. Row text selection must not collapse during unchanged snapshots.
7. **UI lives outside `src/ui/`.** `src/lib/dom.ts` contains text/confirm/help dialogs; `src/lib/operation-ui.ts` builds forms and worktree lists; `src/lib/pairing-scanner.ts` builds camera modal. Migrating only `ui/` would leave substantive PWA interaction surfaces in manual DOM. Pure parsing/helpers may remain TS; dialog markup should become React with controlled ownership/portals.
8. **React ownership cannot overlap manual child replacement.** During migration each host needs one owner. Existing `app.replaceChildren`, stream replaceWith, chrome replaceChildren, progress updates and input value patches must be retired or explicitly isolated from React-managed child nodes. Sanitized Markdown may use a tightly scoped HTML host; retain the sanitizer and link policy.
9. **SCSS and Tailwind can alter pixels globally.** Current CSS order is semantic; tokens/base/icons/chrome and family styles combine in one cascade, while workspace file action styles are imported from its module. Tailwind preflight/reset can change buttons, headings, borders, lists and form metrics. Keep exact baseline tokens/selector specificity/order, explicitly decide reset ownership, compile SCSS independently as needed, and compare computed styles/screenshots before swapping to utilities. Do not redesign layout during migration.
10. **Foreground/network behaviors are orthogonal to component mount.** `main.ts` and session transport listeners jointly manage offline stops, foreground probes, P2P reuse and polling. App rerenders and responsive switches must not register duplicate listeners or cancel healthy connections. Hidden-page transitions must stop key repeats and terminal controller activity.
11. **Scope keys prevent stale UI corruption.** Draft and prompt scope includes daemon, actual session object, pane, mode, view incarnation and revision. A→B→A can be a new view even with same pane ID. Preserve late-result tests; a stale request cannot clear a new operation lock, erase a new draft, alter IME, or focus another screen.

## Test/build infrastructure changes needed

- `tsconfig.json` currently includes only `src/**/*.ts`; add `.tsx` and correct JSX transform; exclude `.test.tsx` as appropriate.
- `src/import-boundaries.test.ts` scans only `**/*.ts` and resolves only `.ts` / `index.ts`. It would silently miss JSX cycles unless extended to `.tsx` and mixed imports.
- `src/style.test.ts` recursively reads literal `@import` paths from `src/style.css` and regex-matches selectors/raw declarations. SCSS nesting, `@use`, Tailwind compilation and renamed files need compiled-CSS or equivalent computed-style assertions. Preserve each guard (touch targets, flex scrollports, viewport locks, contrast, reduced motion, standalone strip, 844x390 landscape geometry), not just test passability.
- Source-reading tests are extensive: `ui/full-terminal.test.ts`, `pane-menu.test.ts`, `list-menu.test.ts`, `home.test.ts`, `connect.test.ts`, `computers.test.ts`, `sheet.test.ts`, `agent-chat.test.ts`, `key-flight.test.ts`; `ui/session/{compose,term,view,slash-pad,echo}.test.ts`; root viewport/network/poll tests. Replace brittle source syntax assertions with actual behavior where JSX makes syntax irrelevant. Do not delete safety invariants.
- Happy DOM suites install globals and import modules once. Existing tests expect synchronous node builders and query immediately after function calls. React test harness must mount into the matching document realm, flush commits appropriately, and unmount/cleanup roots/listeners/timers between fixtures. Older tests may omit `HTMLTextAreaElement`, Event or RAF globals that React needs; fix harnesses centrally where feasible.
- Existing browser scripts: `scripts/terminal-browser-benchmark.ts`, `terminal-command-benchmark.ts`, `live-input-benchmark.ts`, `live-session.ts`. They provide useful transport/render performance entry points but are not an exhaustive screen parity suite.
- Full repository gate remains `./scripts/verify.sh` from repo root; PWA Bun tests + typecheck + production build separately provide quicker module feedback. Do not run genvectors absent protocol changes. This refactor should need no protocol/vector changes.

Browser interaction runs should assert actual input events and mutation call logs, DOM node identity, focus and selection, scroll anchoring, no overflow, console cleanliness, no listener/timer leaks on repeated navigation, and xterm renderer resource ownership. Physical iPhone/Android IME, keyboard, gesture capture, camera scan, standalone safe areas and background recovery remain separately required for a claim of complete physical interaction parity. Stubbed browser tests cannot prove deployed/runtime/phone behavior. No production deployment or daemon upgrade is implied by this source migration.
