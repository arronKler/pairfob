# 减少重复读取与界面等待

本轮完成活动日志解析、状态快照与提示、看板预览、工作区目录加载四项优化。
没有修改加密协议、RPC 字段、服务端资源配置或变更操作的重试规则；尚未部署。
本机 daemon 使用有界分类缓存减少重复解析，未新增云端常驻任务或服务实例。

## 测量结果

| 路径与测量条件 | 优化前 | 优化后 | 解读 |
| --- | ---: | ---: | --- |
| 20 份真实本地 Claude 日志尾部，回放最后一条完整记录，三轮解析中位耗时 | 1,153.115 ms | 78.477 ms | 约 14.7 倍；这是解析 CPU 路径，非完整 Snapshot 或公网建联 |
| 同一日志样本需要重新解析的记录字节 | 约 10.47 MB 尾部窗口 | 43,204 B | 未变化记录复用分类；完整校验读取范围仍保持不变 |
| 20 条重复状态提示＋另一 pane 提示＋离线提示，受控测试 | 22 次发送 | 3 次发送 | 减少 86%；不同 pane 和离线信息保留 |
| 监控先开始、客户端随后重叠请求展示快照 | 2 次 runtime 读取 | 1 次 | 共享计算；权限判断使用的快照仍单独读取 |
| 8 个看板预览，每次读取显式模拟 100 ms 延迟，三轮中位耗时 | 814.2 ms | 406.8 ms | 约 2 倍；请求仍为 8 次，峰值并发从 1 变为 2 |
| 三格看板的单 pane 状态提示 | 3 次预览读取 | 1 次 | 减少 67%；完整兜底轮询保留 |
| 初次只打开工作区“更改”页 | 1 次目录读取；5 次 fixture 读取调用 | 0 次目录读取；4 次 fixture 读取调用 | 去掉未展示目录的读取；Git 状态和本轮文件信息保留 |

真实日志样本每轮校验 10,465,774 字节。基线耗时为 1,132.948、1,153.115、
1,287.593 ms，新版为 90.097、24.325、78.477 ms。机器负载与日志组成影响
具体倍数；样本是在内存中回放已有日志，并非对活跃生产 daemon 的端到端计时。
日志文件未被修改，样本报告不含路径、设备身份、文本内容或活动摘要键。

另一个合成的约 512 KiB 窗口基准中，旧版解析中位 37.3 ms，新版 0.868 ms，
约 43 倍；解析分配量约 696 KB → 25 KB。该结果用于定位解析成本，不能取代
上面的真实日志回放，更不能与之前的建联优化倍数相乘。

工作区目录是按需延后：如果用户随后切到“文件”页，仍会读取一次目录。
因此减少的是不访问文件列表时的无效工作，不是承诺所有工作区操作都少一次请求。
相较于旧路径已经完成预加载的情况，首次切到“文件”页会多一次可见的目录
请求等待，弱网下尤其明显。状态提示合并也引入最多约 20 ms 的批处理等待
（实际送达另受调度影响），在线／离线提示旁路。这两项是明确的延迟与负载
取舍，不能据此声称所有交互体验完全不变。
Git 状态同时支撑文件行标记、分支同步信息和变更摘要，本轮继续读取，未以隐藏
这些能力来换取低负载。

[原始计数、样本与源码哈希](load-reduction-samples.json) 区分了真实日志回放、
受控 daemon 测试和浏览器 fixture；没有把模拟延迟当成公网测量。

## 实现与正确性边界

- 活动日志仍通过受限根目录安全打开、文件身份和读前后元数据校验。逐条检查
  字节摘要与原始偏移，只有完全相同的记录才复用解析结果；原地改写、截断、
  滑动窗口边界、损坏行和半条记录遵循原有扫描语义。每份日志最多缓存 1,024
  个分类，沿用 32 份缓存上限。按日志互斥替代全局解析锁，不同日志不会互相
  阻塞。本轮没有声称磁盘读取量下降。
- 监控与客户端共享重叠的展示快照。监控不能加入事件之前开始的旧读取，而会
  立即启动新的读取；后续客户端可加入它。取消监控等待不会取消其他客户端的
  共享读取。已完成结果不做 TTL 缓存；权限校验路径保持独立。
- 状态提示在 20 ms 窗口中仅合并重复的 reason/pane；离线、在线提示绕过
  批处理。通知投递是另一条队列，没有合并或丢弃通知内容。
- 看板最多两路读取，优先发起焦点 pane。被替换的任务不再发起后续读取，旧
  结果不发布到新页面。单 pane 提示排队合并；提示若在读取中到达，会保留一次
  新鲜的后续读取，并让完整轮询有机会执行。网络不可用、页面隐藏、会话改变
  仍遵循原有阻断条件。
- “更改”页不预读目录；首次进入“文件”页按需读取，并复用原有根目录缓存。
  分页数量保留，旧 daemon 的非 Git 工作区照常首屏加载文件。目录回复不会把
  已打开的详情覆盖回列表。

## 验证与复现

浏览器使用真实生产组件与本地 QA RPC fixtures，检查 390×844、820×768、
1024×768 的触摸操作及 1440×900 的键盘和鼠标操作：切换到文件列表、打开文件、
显示 Git 摘要、加载三个看板预览并从看板打开 pane，全部通过，无横向溢出。
截图位于 `/tmp/pairfob-load-qa/`。这不是实体手机或生产网络验收。

运行 `scripts/qa-load-reduction.mjs` 时，先创建一个 ego-browser task space，
将 `globalThis.PAIRFOB_QA_SPACE` 设置为其 ID，并通过 `ego-browser nodejs`
执行脚本。默认访问本地候选版本 `http://127.0.0.1:5200`；对照需将
`PAIRFOB_QA_VARIANT` 设为 `baseline`，并以 `PAIRFOB_QA_BASE` 指向保存的旧版
模块服务。基线仅用于计数和耗时对照，四种尺寸的交互验收针对候选版本。
浏览器空间已关闭，任务创建的临时 Vite 服务已停止。

日志基准：

```sh
go test ./internal/journal -run '^$' -bench BenchmarkActivityGrowingWindow -benchmem -count=3
PAIRFOB_PROFILE_LOCAL_ACTIVITY=1 go test ./internal/journal -run '^TestLocalActivityProfile$' -v -count=1
```

定向竞态检查、原地改写与滑动窗口一致性检查、旧版本工作区、分页恢复、请求
取消与预览后续读取测试均已通过。真实本地 transcript 扫描已通过；没有本地
会话的提供方不构成覆盖。受影响 PWA 测试运行有 1,213 项通过，一项未修改的
动画终值测试在繁忙机器上读到 1.999998 而非 2，单独复测通过，未放宽断言。
最后一组回归 25 项通过，类型检查通过。

第一次全量 gate 中，Go、脚本和桌面检查通过，PWA 为 5,854 项通过、2 项失败。
失败出现在验证期间另一组会话创建修改涉及的测试；最新源码单独复测 16 项通过，
没有修改断言。完整工作区重新记录源码哈希后重跑 `./scripts/verify.sh`，
**最终退出码为 0**：PWA 5,856 项通过、0 失败，Go（含竞态检测）、脚本、
桌面、Worker、类型检查和构建均通过。共享机器负载较高，本轮完整验证约 33 分钟。

重跑期间另一组工作移除了一份临时 runtime 性能探针测试；删除后的
`go test -race ./internal/runtime` 已补验通过。收尾时又检测到并行的分屏创建

再次运行完整 gate 或重建发布包。本轮四项优化的实现未发生变化。未重新运行
输入未变化的浏览器交互与性能样本，也未将它们计作生产网络或实体设备验收。
