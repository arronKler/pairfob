**Pairfob 优化前后收益汇总（2026-11-13）**

汇总本次系列优化，以及参与审查和修复的并行创建交互改动。本表采用各轮已保存
的测量结果，没有重新跑基准。不同批次使用各自的基线、机器状态和测量范围，
不能将倍数相乘，也不能把微基准视为公网全链路收益。耗时越小越好；“倍数”是
优化前耗时除以优化后耗时。后续多项仍在工作区，表格不代表统一的线上版本验收。

**真实公网链路**

| 优化／指标 | 优化前 | 优化后 | 收益与边界 |
| --- | ---: | ---: | --- |
| Claude 标题预过滤与文件身份缓存：P2P Snapshot 中位耗时 | 2,253 ms | 147 ms | 15.3×；同机 20 panes，每版 6 次；候选复测中位 116 ms |
| 同一批标题优化：新建联到首份配置与 Snapshot 可用 | 6.15–6.29 s | 4.14–4.53 s | 中位比约 1.44×；每版仅 2 次，不能推广为普遍收益 |
| ICE 与 relay 认证并行：新拨号到 P2P ready 中位耗时 | 4,183 ms | 3,386 ms | 观察值下降 19%；每版 4 次，包含网络波动，不能全部归因于改动 |
| 认证完成后剩余的串行 ICE 等待 | 192–198 ms | 4 个样本均为 0 | 直接证实移出关键路径约 195 ms；不是省去 ICE 本身的工作 |

这些测量使用真实 WebSocket、WebRTC、pairfob.com relay 和本地 Herdr；不包括
完整 PWA 资源加载和渲染，也不是实体手机测量。已有 P2P Ping 比 relay Ping
更低的差异不是本轮新交付的收益。来源：[Snapshot 实测](live-connection-performance.md)、
[ICE 实测](p2p-preparation-performance.md)。

**可靠性改进：没有独立的速度倍数**

| 改动 | 原行为／风险 | 当前行为／收益 |
| --- | --- | --- |
| 终端收发锁拆分 | 输出发送可阻塞认证请求接收 | 两个方向独立；迁移和销毁仍同步密钥生命周期 |
| 交互回复优先、终端分片让出发送机会 | 大帧可持续占据发送路径 | 交互优先，连续 8 次后允许 bulk，避免饿死 |
| relay 按字节准入 | 主要依赖 128 帧队列限制 | 增加 266,264 B 软预算；保留原硬队列上限；并发会话可短暂超额 |
| P2P 写入背压 | 可能在硬上限处失败 | 加密前等待可写，1 MiB 软预算／2 MiB 硬上限，10 s 等待上限，支持取消 |
| transcript 与展示读取分开 | 竞争同一展示读取通道 | transcript 独立 4 槽，展示保留 8 槽；超龄排队读不再执行 |
| 连续短连接的重连退避 | 短暂成功可反复重置重连延迟 | 保留第一次立即恢复；短于 10 s 的连接延续指数退避 |
| 统计写入异常隔离 | 统计异常可能中断转发或清理 | 记录失败计数，不中断 opaque FWD |
| 原生 crypto 能力回退与取消 | 使用既有 JS 实现 | 不支持时回退；失败验签不回退；取消后不发送迟到认证消息 |
| ICE 预热所有权与清理 | 认证后才开始准备 | 单次转移；失败、关闭、隐藏和网络变化清理未消费资源 |
| 共享快照的新鲜度与取消 | monitor 和 phone 分别计算 | 后事件 monitor 不接纳旧读取；取消一个等待者不取消其他等待者 |
| 创建后旧 Snapshot 防护 | 创建流程原先等待 catalog | 提前打开后保留新 pane，避免旧响应误判其消失；后台 catalog 失败不覆盖成功提示 |

来源分别为前述[网络](network-transport-performance.md)、[认证](connection-performance.md)、
[ICE](p2p-preparation-performance.md)、[负载](load-reduction-performance.md)和[创建](create-pane-performance.md)报告。

**成本、取舍和撤回项**

- 原生 crypto 的连接样本：WebSocket 1 → 1、Hello1 1 → 1、客户端帧 8 → 8、
  编码字节 834 → 834；ICE 样本：WebSocket 1 → 1、PeerConnection 1 → 1、
  relay 发送 10 → 10。没有新增云端实例、TURN 服务或常驻 socket 池；未测量
  生产账单，不能将“无新增资源”表述为已经量化的账单降幅。
- ICE/STUN 提前启动后，认证最终失败的尝试也可能已经做过准备工作；成功连接
  请求量不变并不代表所有失败路径的本地／STUN 工作完全不变。
- 状态提示批处理引入最多约 20 ms 合并等待；在线／离线提示旁路。目录按需
  加载使首次“更改 → 文件”可能多一次可见 RPC 等待，之后使用原有缓存。
- 删除 shell 就绪等待的尝试已撤回，不计为优化收益。独立审查确认它会导致慢
  shell 下 `agent_pane_busy`，而不是等待。当前恢复最多 5 s 的只读检查、
  100 ms 轮询和 300 ms 稳定窗口；Agent 启动不自动重试。三条创建路径回归、
  真实 3 秒慢 shell 验证、runtime 竞态检查和 vet 均通过。
- 各批次具有对应测试和源码快照，但未对“所有优化叠加后的当前工作区”重做
  统一公网 A/B、实体手机、长时间弱网及后台驻留验收。已有证据不支持整体
  建联、原始带宽或所有用户体验统一提升 10 倍。
