Changes

做了什么

四个 gate 并发

四个 gate 读写不同目录，只读 checkout；总墙钟从“相加”变成“最慢者”。

scripts/verify.sh

Go 测试名级分片 + race-first 覆盖

从源码列出测试名，按实测权重贪心分片；大包内测试与子测试拆分。每个测试只在 race 下执行一次：只有 build tag 让两个构建的测试文件不同时，才补跑普通构建。计划工作量从 2912.7s 降到 1580.9s（−46%），每片 131.3–132.0s。

scripts/go-test-shard.tsscripts/go-test-timings.jsonscripts/verify-go.sh

恢复 Go 测试缓存语义

默认每个分片走 go test，输入未变的包直接回放 Go 测试缓存，重复验证只花秒级；PAIRFOB_VERIFY_BINARIES=1 可切回预编译二进制的冷启动路径。

scripts/verify-go.sh

固定 Bun 版本解析

入口按 .bun-version 解析 Bun：优先 ~/.bun/bin/bun，匹配 1.4.3 才继续，否则给出安装命令并停止。Homebrew 1.3.10 会忽略 --parallel，此前整门因此多花约 540s。

scripts/verify.sh

PWA 测试结果缓存

输入（pwa/、proto/、分片器、时序清单、Bun 版本、locale 环境）逐字节一致时复用上一次绿色的 shard；键由 git tree/diff/未跟踪文件内容计算，约 0.3s。失败绝不写入，PAIRFOB_VERIFY_CACHE=0 可强制全跑。命中实测 0.5s 跳过整套测试。 同时修复了 step() 在 || 上下文吞掉失败、把失败步骤打印成 passed 的缺陷。

scripts/verify-cache.tsscripts/verify-web.sh

tsgo 类型检查

锁定原生 TypeScript 预览版，用一个程序同时覆盖 src 与 qa；保留 typecheck:tsc 作为上游编译器回退。Worker 包同样切换。

pwa/tsconfig.all.jsonpwa/package.jsonworkers/pairfob-origin/package.json

Web gate 四部分并发

tests / static / build / workers 互不依赖；static 内部四项、workers 内部五项也各自并发，并用 --only-failures 压缩日志。

scripts/verify-web.sh

Scripts gate 全并行与镜像守卫

shell 语法、proto、插件、文档、脚本测试同时运行；公开仓库的 5 个 lockfile 都扫描内网镜像地址 bnpm。

Boundary

结论与边界

重复验证已实测达成 10×：缓存命中整门 134s，对比基线 1900–2100s 约 14–16×；冷态整门 871s（3.5–4×）；Go gate 11.2×。

测量链是真实的：load 1.95 的窗口里 PWA 全量 233s 全绿并写入缓存；随后两次完整 verify.sh 分别为 214s（load 12） 与 134s（load 16）。134s 的分解是 Go 124s（vet 17s、vuln 40s、race 缓存回放约 100s）、scripts 62s、 web 134s（QA 114s、build 117s、Worker integration 70s 并发，PWA 测试 0.5s 复用）；唯一失败是 desktop 在 format 之后因缺少 Metal 组件退出。冷态 871s（load 21.8）时 Go、scripts 与全部 PWA 测试均通过，只有负载导致的 wrangler e2e 超时与 desktop 环境失败。缓存只复用绿色结果：load 28/34/36 下三次失败运行（1、38、6 个用例） 都没有写入。

  • 重复整门的尾部换成了 Go 缓存回放（124s）、PWA QA/build（117s）与 scripts（62s）；PWA 全量的 754 CPU-s 只在首次或输入变更时支付。
  • 冷态下界是算术：验证本身约 1800 CPU-s，12 核满载下限约 150s；基线 1900–2100s 对应冷态最多约 12–14×，但共享机器只给到 2–4 个核，所以冷态实测停在 3.5–4×。
  • Bun 版本会改变验证语义：Homebrew 1.3.10 让 660 个文件退化为串行，整门多花约 540s；入口现在按 .bun-version 解析并拒绝错误版本。
  • CI 的端到端 8m26s 里 Linux 验证只占 2m17s，剩余是 macOS runner 排队 5m23s 与 desktop 编译 2m29s；继续压脚本不会缩短这条墙钟。
  • 第二次本机整门在 load 7.5 启动、数分钟后被外部负载抬到 53：PWA QA 的 37 个测试跑了 941s、Go 分片与 30s/60s 用例成批超时，整门 1233s；同一套代码在 load 21.8 时只有环境类失败。外部负载是本机端到端数字的主导变量。
  • 三项 PWA 失败与 wrangler e2e 失败均可在同负载下串行复跑通过；race 下 32MiB-download 单测在 12 路并发时被内存带宽拖到 162s，独占时仅 13s。

Cache

缓存语义已恢复

默认分片走 go test，未变输入的包回放 Go 的测试结果缓存，重复验证不再重跑全量； PAIRFOB_VERIFY_BINARIES=1 保留预编译二进制路径，适合缓存清空后的首次冷启动。 两条路径都执行同一套 race-first 覆盖，不删除任何测试。
